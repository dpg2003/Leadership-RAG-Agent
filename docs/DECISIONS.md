# Decisions

Each entry: what we chose, what we rejected, and why. Newest at the bottom.

## D1. No LinkedIn as a source

- **Chosen:** The company's own site, SEC EDGAR, and one web search API.
- **Rejected:** Scraping LinkedIn (directly or through scraping proxies or APIs that resell its data).
- **Why:** LinkedIn's User Agreement prohibits scraping. We accept the cost: weaker coverage of VPs and department heads, who often appear only there. That gap is measured (coverage-scout, also LinkedIn-free) and listed under "Known misses" in `VALIDATION.md`. The same rule covers any site whose ToS forbids automated access.

## D2. SQLite relational store, not a vector store

- **Chosen:** SQLite with a plain `schema.sql`, committed per company at `data/<domain>/leadership.db`.
- **Rejected:** A vector store or embedding retrieval over raw pages. Also rejected: Postgres as a runtime dependency.
- **Why:** The target questions are structured: filter by role ("who's the CTO"), count ("how many VPs"), and look up a field ("where is the CEO based"). A relational model answers them exactly, while similarity search makes counts and filters approximate. SQLite needs no server, so the repo stays clone-and-go.
- **Postgres compatibility:** The schema avoids SQLite-only features. Booleans are `INTEGER` 0/1, timestamps are ISO-8601 UTC `TEXT`, and enums are `CHECK` constraints. The one swap is that `id INTEGER PRIMARY KEY` becomes `id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. Queries in `repository.py` use `?` placeholders, which a Postgres driver would replace with `%s`.

## D3. Resolved view and audit trail are separate tables

- **Chosen:** `facts` stores every claim (field, value, source, evidence snippet). `people` and `roles` store the resolved current view, derived from facts.
- **Rejected:** One `people` table with the source columns inline.
- **Why:** Inline sources can only keep one source per field, so conflicts disappear. With separate facts, the chat agent can show every source and point out disagreements.
- **Enforced in the repository, not just the pipeline:** A fact needs a source and a non-blank snippet (also a DB `CHECK`). `location`, `bio`, and each role's `title_raw` can only be written if a matching fact exists for that person. Otherwise `ProvenanceError` is raised.
- **A person can't exist without evidence.** `upsert_person` takes a source and a snippet and writes the `full_name` fact in the same call. `update_person_resolved` also requires the resolved `full_name` to match a fact. Every fact's source must belong to the person's company.
- `people.profile_url` must be the URL of a row in `sources` for the same company (checked on write), not a separately sourced claim.
- **Facts are rebuilt each run, not accumulated.** Before resolving, `clear_people` deletes the company's people, which cascades to roles and facts. Re-extraction then rebuilds facts from the cached raw documents. The durable record is `sources` plus the raw cache. Rejected: keeping facts across runs. Stale claims from older runs would build up, and conflict handling would need a per-run version, which is too much for this scope.
- Writes go through `Repository.transaction()` (commit on success, rollback on error), so a failed run never leaves a half-resolved company behind.

## D4. Schema details (reviewed with Daniel in Phase 0)

- **Source priority is derived, not stored.** `SOURCE_PRIORITY` in `models.py` maps `sources.source_type` to a priority: company_site (0) beats sec_filing (1), which beats search (2). Rejected: a `facts.source_priority` column, which would duplicate `source_type` and could drift from it.
- **`source_count` is computed in the query** (distinct `source_id` across the person's facts). Rejected: storing it on `roles`, where it could go stale after a re-resolve.
- **No `exec` seniority.** President maps to `c_level`. `title_raw` always keeps the original title, so nothing is lost. Allowed seniorities: `c_level | vp | head | founder`.
- **General Counsel / Chief Legal titles (corrected by Daniel after Phase 3):** `c_level` only if the person is listed as an executive officer in the latest proxy (DEF 14A); otherwise `seniority = head`, `function = legal`. This applies to "General Counsel", "Chief Legal Officer", "CLO" and combinations such as "SVP, General Counsel". Without a proxy (private companies), they are always `head`. This applies to past roles too (Anne Hoge, Chief Legal Officer 2019–2020, before the IPO, is stored as `head/legal`, not current), because the test is about the latest proxy. The original rule (always `c_level`) made Lucas Moskowitz (SVP, General Counsel, not in the proxy) a second legal chief next to Dan Gallagher (Chief Legal Officer, in the proxy). Implemented in `resolve._role_keys`; `titles.py` only marks such titles `legal_chief`.
- **Dedupe key:** `people` is unique on `(company_id, normalized_name)`. `normalize_name` strips accents, case, punctuation, honorifics and suffixes, and middle initials. It deliberately does **not** merge nicknames ("Vlad" vs "Vladimir"). A wrong merge would combine two people's facts, which is worse than a duplicate that shows up in validation.
- **`facts.field`** is restricted to `full_name | title | location | bio`.
- **`collection_runs.stats_json`** holds tokens in and out, cost, document counts per source, people found, and rejected extractions with reasons.
- **Counts are of people, not roles.** A CEO who is also a co-founder counts once in "how many leaders".

## D5. Configuration via environment

- `.env` at the repo root is loaded automatically (`python-dotenv`). Variables: `ANTHROPIC_API_KEY`, `TAVILY_API_KEY`, `SEC_USER_AGENT` (used as-is, e.g. `"Jane Doe jane@example.com"`, as SEC requires), and `LLM_MODEL` (blank means `claude-sonnet-5-5`).
- Only `ANTHROPIC_API_KEY` is needed to run chat, eval, and the UI against the committed data. `TAVILY_API_KEY` and `SEC_USER_AGENT` are only needed for `leadership collect`. A missing key raises an error that names the variable and says where to get it.

## D6. Narrow nickname merge rule (reviewed with Daniel after Phase 1)

- **Problem:** The same person appears under different first names across sources. Robinhood's site likely says "Vlad Tenev" while the SEC filings say "Vladimir Tenev". Exact normalized-name matching (D4) would create two people.
- **Chosen:** `compare_identity` in `pipeline/resolve.py` merges two records (SAME) only when **all** of these hold:
  - same company;
  - same last name;
  - the first names match: identical, one is a prefix of the other (shorter one at least 3 letters, e.g. Vlad/Vladimir), or both are in a small, explicit nickname map (Bob/Robert, Bill/William, ...);
  - at least one overlapping role `function`.
- **Close but not merged** is returned as POSSIBLE_DUPLICATE and listed in `VALIDATION.md` for Daniel to decide. This covers: same last name with matching first names but no overlapping function; same last name and same first initial; same first initial and last names at least 0.8 similar (e.g. Steven Quirk / Stephen Quirke); or whole-name similarity of 0.85 or higher.
- **Every non-exact merge is also listed** in `VALIDATION.md` ("merged by nickname rule"), so a wrong merge is visible.
- **Accepted risk:** The prefix rule merges "Chris Lee" and "Christine Lee" if their functions overlap. A test documents this case. The reviewer-visible merge list is the mitigation.
- **Rejected:** fuzzy matching (edit distance) as the merge criterion, which risks silently mixing two people's facts. Also rejected: an LLM judging identity, which is non-deterministic and hard to audit. Also rejected: a large nickname database, which goes beyond what two test companies need.

## D7. Tavily as the one web search API

- **Chosen:** Tavily (`search_depth=basic`, 8 results, `include_raw_content=text`), with 10 targeted queries per company (CEO, CTO, CFO, "chief" officer, VP, "vice president", "head of", appoints/hires/names, leadership team, founder).
- **Rejected:** Brave and Serper. Both return snippets only, so every result page would need a second fetch (more requests, more robots.txt and ToS checks, more code). Tavily returns the page text in the same call.
- **Disambiguation:** Every query adds the company's site host ("Campfire campfire.ai"), because "Campfire" alone matches unrelated organizations. Results from unrelated organizations still get through (campfire.org, campfire-interactive.com, robinhood.org), so extraction must check that a person works at *this* company (Phase 3).
- **Trust:** Pages Tavily returns are `source_type=search` even when the URL is on the company's own domain, because we didn't fetch them ourselves. That makes them the lowest priority.
- **Cost:** 10 API calls (basic = 1 credit each) per company per fresh run. Cached query responses mean re-runs cost nothing.

## D8. Excluded domains

- Search results from domains whose ToS forbids scraping, or that resell scraped profiles, are dropped both at query time (`exclude_domains`) and on cached results: linkedin.com, x.com, twitter.com, facebook.com, instagram.com, zoominfo.com, rocketreach.co, crunchbase.com, glassdoor.com, apollo.io, signalhire.com, contactout.com, lusha.com, theorg.com, comparably.com, salary.com, dealroom.co, clay.com, exa.ai, tavily.com. The last three were added after the Phase 2 review: their pages (tavily.com/knowledge, clay.com/dossier, exa.ai/websets) are profile aggregators, and the Tavily page cites LinkedIn follower counts. They are not primary sources.
- When a domain is added later, its text is purged from the cache files (so it never gets committed), and its URLs are still reported as skipped.
- Our own fetcher refuses linkedin.com outright, whatever robots.txt says. **Redirects are followed by hand** (at most 5 hops). Before each hop is requested it is checked against the banned-host list and robots.txt, and rate-limited. A refused hop is cached as `blocked`, so warm runs stay offline. (The Phase 2 review found that letting httpx follow redirects checked the target only *after* requesting it.)
- robots.txt status handling: 2xx is parsed; 401, 403 or 5xx means disallow everything (5xx per RFC 9309; 401/403 follows CPython's stricter rule); any other 4xx means allow; unreachable means disallow.

## D9. HTML to text with selectolax, not trafilatura

- **Chosen:** `selectolax` (lexbor backend). It drops script, style, noscript, svg, template, iframe and head, then keeps all visible text, one block per line.
- **Rejected:** trafilatura. It is built to extract an article's main body and treats bylines, nav and team grids as boilerplate. Campfire's leaders appear mostly in blog bylines ("John Glasgow / CEO & Founder"), so trafilatura would discard exactly the evidence we need. The cost of our choice is more text per page; the Phase 3 keyword pre-filter offsets it.

## D10. Raw cache layout

- Path: `data/<domain>/raw/<source_type>/<sha256(url)[:20]>`, with `.meta.json` (URL, final URL, status, `fetched_at`), `.body.gz` (raw bytes; gzip with `mtime=0` so re-fetching the same content gives the same file), and `.txt` (the extracted text).
- `sources.raw_path` points to the **`.txt` file**: the exact text that extraction read and that the evidence-snippet check runs against.
- Errors (404, 403, network) and robots.txt files are cached too, so a re-run with a warm cache makes **zero** network requests (verified: `network requests: 0 · search API calls: 0`). `--refresh` re-fetches.
- `raw/manifest.json` lists every document plus everything skipped, with the reason, per source. A blocked or empty source shows up there and is never silently dropped.
- The cache is local only and is **not committed** (D14).

## D11. Company resolution and SEC matching

- The input domain names the data folder (`meetcampfire.com`), but crawling uses the final URL after redirects (`https://campfire.ai/`). Both hosts count as "on site".
- The company name comes from `og:site_name` or the first part of `<title>`, and `--name` overrides it.
- **The SEC match is deliberately conservative.** Without `--ticker`, a match is accepted only if exactly one registrant's title starts with the company name as a whole word. "Robinhood" matches Robinhood Markets, Inc. *and* Robinhood Ventures Fund I/II, so the lookup refuses to guess, and the collect command passes `--ticker HOOD` explicitly. Rejected: fuzzy name matching, because a generic name like "Campfire" could latch onto an unrelated registrant and import someone else's executives as "authoritative".
- **Robinhood's 10-K has no executive-officers section.** Item 10 incorporates it by reference from the proxy. The **DEF 14A** is therefore the authoritative SEC source. The 10-K is still kept, because it names officers in its exhibits and signatures.

## D12. Adapters return a report, not a bare list

- `discover(company)` returns an `AdapterReport` (documents, skipped URLs with reasons, notes) instead of `list[RawDocument]`. This departs from the interface in the initial prompt on purpose: the "tell me if a source is blocked or empty" rule needs the skips to be data, not log lines.

## D13. investors.robinhood.com: keep Tavily's copies, flagged (decided by Daniel after Phase 2)

- **Finding:** investors.robinhood.com answers every non-browser client, including requests for `/robots.txt` itself, with an Akamai "Access Denied" 403 (`errors.edgesuite.net` reference). Checked with our User-Agent and with curl's default one (2026-11-24). No robots.txt is ever served, so there is **no explicit Disallow**; it is generic bot protection. robinhood.com's own robots.txt does not mention the investors host.
- **Chosen:** Keep the 18 pages Tavily returned from that host, at `source_type=search` (lowest trust). We never request those pages ourselves: our robots rule treats a 403 robots.txt as "disallow everything" (D8). We did not retry with a browser User-Agent, which would be evading the block.
- **General rule, in code:** for every search result on one of the company's own hosts, `SearchAdapter` checks that host's robots.txt (only robots.txt is requested). An explicit Disallow for the path drops the result; a 401/403/5xx or unreachable robots.txt keeps it with `meta.direct_fetch = "blocked: ..."`. Third-party hosts are not checked: Tavily fetched them, not us.
- **Review:** every record whose only evidence comes from a `direct_fetch` = blocked page is marked in `VALIDATION.md` for Daniel to hand-check in a browser.
- **Rejected:** excluding them. These pages are the only source for Robinhood's VP-level people (Kerbrat, Rao, Fatehpuria and others), and the block is not a stated crawling policy.

## D14. Raw cache is not committed (decided by Daniel after Phase 2)

- **Chosen:** `data/*/raw/` is gitignored. Each company commits only `leadership.db` and a readable `leadership.json` export. Every fact in them carries its source URL, an evidence snippet and `retrieved_at`, which is enough for a reviewer to check a claim against the live page.
- **Why:** The cache holds full copies of third-party news pages and SEC filings. Redistributing those in a public repo is a copyright problem; the short evidence snippets are not.
- **Cost:** a fresh clone cannot re-run extraction offline. Re-collection (`leadership collect`) needs `ANTHROPIC_API_KEY`, `TAVILY_API_KEY` and `SEC_USER_AGENT`; the README says so. Chat, eval and the UI need only `ANTHROPIC_API_KEY`.
- **Rejected:** committing the ~11 MB cache (supersedes the earlier plan in D10).

## D15. Company-site crawl limit is per run

- `--max-pages` (default 60) sets how many top-ranked company-site URLs are fetched. Campfire is collected with `--max-pages 120`: its leaders appear mostly in blog bylines, and the default left 35 posts unfetched. With 120 it fetched 86 pages and hit no cap. Robinhood keeps 60: more newsroom pages there mostly add stale appointment posts and LLM cost.

## D16. Currency and confidence rules (Phase 3; proxy and 18-month rules decided by Daniel)

All deterministic, in `pipeline/resolve.py`. The LLM only reports what a page says (`status`: current / former / incoming / unclear).
- **One role per (seniority, function) per person.** The best claim names it: source priority (company_site > sec_filing > search), then newest date.
- **Former wins** unless a current claim for that role is strictly newer (undated counts as oldest). A "former" next to the title in the snippet overrides the model's status. Test: Jason Warnick ("former Chief Financial Officer" in the 2026 proxy) is never current, with or without the 2021 newsroom post.
- **Proxy rule:** for C-level roles, a **dated** newsroom or search claim older than the latest DEF 14A, for a role the proxy doesn't list for that person, is `is_current = false`. SEC claims are exempt. **Undated** claims (e.g. the investors.robinhood.com leadership page) can't be shown to be older: they stay current and are listed in `c_level_not_in_proxy_undated`. The proxy lists only Section 16 officers, so a Chief People Officer or CISO is normally absent from it. (The first run applied the rule to undated claims too and wrongly retired 7 people. Fixed and tested.)
- **Promotion rule:** an older title is superseded by a later dated title in the same function (Gretchen Howard: VP of Operations in 2018, then COO in 2019). Founder roles are never superseded.
- **Confidence per role:** `high` = an SEC filing, or 2+ sources including the company site. `medium` = the company site, or 2+ sources. `low` = a single search result. **An uncorroborated single-source role last dated more than 18 months ago is `low`** and listed (`stale_single_source`). A person's confidence is that of their best current role.
- **Listed for review, not decided:** two current holders of the same C-level seat (`seat_conflicts`, e.g. Campfire's two CTOs); sources that disagree on currency (`conflicts`); different locations; nickname merges; possible duplicates; records from bot-blocked hosts (D13).
- People with no current role are kept (with their facts), so "who was the CFO before?" can be answered. Lists and counts include only current roles.
- **Rejected:** letting the LLM decide currency or confidence. It doesn't know other sources or the proxy date, and its answer isn't auditable.

## D17. Extraction: structured outputs, cached, pre-filtered (approved by Daniel after Phase 3)

- **Chosen:** `messages.parse(output_format=Extraction)` (Pydantic, `effort=medium`), one call per pre-filtered document, 4 in parallel.
- **Rejected:** tool use with a forced tool choice. `claude-sonnet-5-5` rejects forced `tool_choice` (HTTP 400). Structured outputs guarantee the schema without a fake tool. The spec's "tool use + Pydantic" intent (schema-validated output) is unchanged.
- **Pre-filter:** keep ±3 lines around role words (chief, officer, VP, head of, founder, ...) plus date lines. For SEC filings, use the executive-officers section, else the signatures. Pages with no role word skip the LLM. About 12% of documents are skipped.
- **Context:** the prompt names the target company and domain, and asks for the employer plus a `works_at_target_company` flag. That flag rejects customers, partners, and homonymous organizations (campfire.org, robinhood.org).
- **Cache:** responses are cached at `data/<domain>/raw/_extractions/` (gitignored with the rest of the raw data), keyed by model, prompt version, URL and exact input. Re-resolving costs $0. `--reextract` forces new calls. `stats_json` reports both this run's cost and the cost of the cached responses.
- **Refusals / truncation:** a response without structured output is recorded in `extraction_errors` and that document is skipped. No server-side fallback model: a refusal is unlikely on public leadership text, and a silent model switch would muddy cost and provenance.

## D18. Evidence check, with literal re-anchoring

- A claim is kept only if all of these hold: the name appears in the cached source text; the snippet appears literally in it (whitespace, curly quotes and dashes don't count); the snippet contains the last name and the exact title; the title passes the title rules (`titles.py`); the model says the role is held at the target company; and the name has at least two tokens.
- **Re-anchoring:** the model often takes the title from a heading but quotes a sentence that rewords it ("Vice President, Corporate Finance & Investor Relations" vs "Vice President of Corporate Finance and Investor Relations"). When the exact name and exact title are both in the source within 200 characters, the stored snippet becomes that literal span (`Claim.reanchored`). This cut Robinhood's rejections from 22 to 7 without accepting anything not literally on the page. **Tightened in D22:** name and title must be in one block, not within 200 characters. Rejected: fuzzy snippet matching, which would accept paraphrases.
- Location, bio and page date each need their own verified evidence, or they are dropped (NULL). A rejected claim is kept in `stats_json.rejections` with its reason.
- **Charset fix found here:** SEC filings declare ASCII but contain cp1252 bytes. Decoding them as UTF-8 put `�` in place of apostrophes, so no quote could match. `FetchResult.text_body` now tries the header charset, then UTF-8, then cp1252.

## D19. Schema additions (Phase 3; approved by Daniel)

- `sources.published_at` (page or filing date, when verified), `facts.is_current` (whether that source presented the title as current), and `roles.as_of` / `roles.note` (newest evidence date; why a role is not current, disputed, or low confidence). All nullable. Missing evidence stays NULL.
- `sources` are rebuilt each run together with people and facts (D3). Only sources that back a stored fact are written.

## D20. Fixes from the Phase 3 review

- **Title rule refinement (applies D4):** "C-level" means the company's own C-suite. A title that also carries a VP token is VP-level: "Vice President and Chief Information Security Officer" and "Vice President and Chief Operating Officer, Robinhood Financial". So is a subsidiary presidency ("President of Robinhood UK ..."). General Counsel is handled by D4 (C-level only if in the latest proxy). Company and subsidiary names ("Robinhood Financial") are stripped before a function is assigned, so "Financial" no longer means finance. Without these rules, "how many C-level" was inflated, and there were false seat conflicts (Koller showing up as a second CFO).
- **One document per canonical URL** (lowercase host, no `www.`, no `/us/en` locale prefix, no trailing slash). Discovery keeps the higher-priority copy. Before this, the same newsroom post under two URL spellings counted as two corroborating sources (Zigaitis and Ashkenas were `high`). It also let a role escape the 18-month single-source rule. Robinhood went from 86 to 79 documents.
- A role retired by the proxy rule now reports the dated claims that were retired (title, `as_of`), not an unrelated undated claim.
- Re-anchored evidence (D18) is listed in `review.reanchored` (person, title, URL, snippet), so it can be hand-checked: on a team grid, the nearest title could belong to a neighbour.
- Prices in `extract.py` cite the pricing page and the date they were checked. The client sets `timeout=120s, max_retries=3` explicitly.

## D21. SEC 8-K Item 5.02 filings (decided by Daniel after Phase 3)

- **Problem:** Jeff Pinner's departure as CTO (May 7, 2026) was known only from Tavily's copy of an 8-K, at search trust. It came after the 2026-04-22 proxy, which still lists him.
- **Chosen:** the SEC adapter also fetches every 8-K whose `items` include **5.02** (departure or appointment of officers) filed on or after the older of the latest 10-K and DEF 14A (at most 10). They come straight from EDGAR with the SEC User-Agent and are stored as `sec_filing`. Discovery's canonical-URL dedupe makes the SEC copy replace Tavily's copy of the same URL. The pre-filter sends an 8-K whole (they are short; the content is before SIGNATURES).
- **Result:** the 8-K filed 2026-05-08 confirms the separation ("would be separating from his position, effective the same day"). Pinner is not current, with high confidence. The 8-K filed 2026-06-26 adds Dara Bazzano (Chief Accounting Officer). Cost: 2 LLM calls, $0.02.
- **Rejected:** trusting the search copy (it is the same document, but provenance should say SEC), and fetching all 8-Ks (most are earnings releases).

## D22. Affiliation must be stated in the evidence; re-anchoring within one block (decided by Daniel after Phase 3)

- **Affiliation:** besides the model's `works_at_target_company` flag, the evidence must itself tie the person to the company. Accepted when:
  - the source is one of the company's own SEC filings (adapter-fetched, or a sec.gov URL under the company's CIK found by search, such as the 2021 S-1);
  - the snippet names the company (its name, or the domain/site host stem);
  - or the page is the company's own (company site, or a search result on a company host) and is a people page (the path is `/team`, `/about`, `/leadership`, `/management`, `/governance`, ..., optionally followed by one slug such as `/management/vlad-tenev`), or the snippet speaks in the first person ("my", "our", "we"; not "us", which also matches "US").
- **Known looseness:** the company-name match is a whole-word match, so a common noun counts ("around the campfire"). Accepted: it only matters on a page that already passed the model's `works_at_target_company` check.
- Otherwise the claim is rejected with reason "evidence does not state an affiliation with <Company>", logged in `stats_json.rejections`.
- **Effect:** Nick Jezienicki (byline on the Atlar partner post) is rejected. **Brendan Doyle (Head of Product) is also rejected:** all eight of his claims are bylines on Campfire's blog that don't name Campfire. Alexandra Roveda stays ("Campfire appointed Alexandra Roveda vice president of enterprise"). A name match alone can't tell two companies named Campfire apart; the phase reviewer checked the cached page, which describes Campfire's AI-native ERP. She is a single-source, low-confidence record for the Phase 4 hand-check. Robinhood loses only redundant claims (quote attributions, Wikipedia); no current person.
- **Re-anchoring tightened:** when the model's quote rewords the title, the stored span must hold the exact name and exact title inside **one block**: the same text line, one markdown table cell (search text), or the same innermost HTML block element (`fetch.html_blocks`, kept as `RawDocument.blocks` for company-site and SEC pages; `doc.text` and the LLM cache are unchanged). A name in an `<h3>` with the title in the next `<p>` is two blocks and is not paired. **Flattened text** (search results have no HTML structure; the Robinhood IR leadership page arrives as one 1,500-character line) is stricter: the title must directly follow the name with only separators between them. In every case, a span that contains another name extracted from the same page is refused. Found by the phase reviewer: without this, "Robb Baldwin" could be paired with Pooja Anand's title on that line. This is stricter than needed for one-person profile pages (the IR `/management/<name>` pages lost those claims), but no person was lost: each also appears on the IR leadership page in one line. Tests cover an HTML team grid, markdown table cells, the flattened IR line, and a sentence with another name in between.
- **Confidence:** a role supported only by re-anchored evidence from one source is `low`. Corroboration from another source lifts it. Re-anchored records stay in `review.reanchored`.
- **Rejected:** accepting company-blog bylines (guest and partner authors are common: the Atlar post), and requiring the company name in every snippet (that would drop the company's own team and IR pages).

## D23. Founders are current leadership only with a current operating role (decided by Daniel after Phase 3)

- A founder role is current only if the person also holds a current non-founder role. Otherwise it is stored as `is_current = false` with the note "founder (historical): no current operating role in the collected data", and the person is excluded from current leadership counts. Listed in `review.founder_historical`.
- **Effect:** Baiju Bhatt (co-founder; his C-level roles are retired by the proxy rule) is not current. John Glasgow and Vlad Tenev (CEO and founder) are current in both roles.

## D24. Display names and a deterministic export (decided by Daniel after Phase 3)

- **Display names** drop professional credential suffixes (CFA, CPA, PhD, MBA, MD, JD, Esq., ...): "Stephanie Guild, CFA" is shown as "Stephanie Guild". The `full_name` fact keeps the name exactly as the source wrote it. Generational suffixes (Jr., III) stay. The same list is stripped from the dedupe key (`normalize_name`), so "Jane Doe, JD" and "Jane Doe" are one person. Leading "Dr." stays; it is not a suffix.
- **Seat conflicts** compare the C-suite seat a title names ("Co-founder / CTO" and "Chief Technology Officer" are one seat), not the function. CFO and Chief Accounting Officer are both finance, but they are different seats.
- **Deterministic `leadership.json`:** re-running on unchanged data gives a byte-identical file (checked for both companies).
  - Fact `extracted_at` and person `updated_at` come from when each LLM extraction was made, stored in the extraction cache, not from the run time.
  - The export has a `collection` block with the run's stable statistics. Per-run numbers (duration, this run's calls, tokens and cost, network and search-API counts) stay only in the DB's `collection_runs.stats_json`.
  - Facts are ordered with a full tie-break.
  - Extraction caches written before this field existed get `extracted_at` from the cache file's modification time, once (an approximation, written back to the cache).
- `leadership.db` still changes on each run (a new `collection_runs` row); the JSON is the reviewable diff.
